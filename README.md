# F-15C Eagle 비행 시뮬레이터 (three.js)

F-15C를 기준으로 한 6자유도(6-DOF) 물리 기반 **1:1 공중전** 시뮬레이터입니다. 빌드 과정 없이 브라우저에서 바로 실행됩니다.

## 실행

Python 3만 있으면 됩니다(추가 패키지 없음). 저장소를 받은 폴더에서:

```bash
# Windows
python server.py
# macOS / Linux
python3 server.py
```

브라우저(Chrome·Edge·Safari 최신판)에서 <http://localhost:8615/> 를 엽니다. three.js r170을 CDN에서 불러오므로 인터넷 연결이 필요합니다. 포트를 바꾸려면 `python server.py 9000` 처럼 뒤에 번호를 붙입니다.

> `index.html`을 파일로 직접 열면(file://) 모듈·GLB 로드가 막히므로 꼭 서버로 엽니다.

- 비행 모델 수치 검증 페이지: <http://localhost:8615/tests/fm-test.html>

## 게임 방식: 1:1 공중전

적 F-15 한 대와 같은 고도·속도로 8 km 정면 대향 출발. 서로 지나친 직후(머지) FIGHT'S ON 신호가 나기 전에는 양쪽 모두 사격·미사일 발사 불가.
- **신병·베테랑·에이스**: 미사일 + 기관포 (플레이어 AIM-9X 4·AIM-120 4발, 적 신병 R-73 2 / 베테랑 R-73 2·R-77 1 / 에이스 R-73 4·R-77 3)
- **엘리트·전설**: 기관포만 (기총전으로 학습한 강화학습 정책)

(이전의 활주로 이륙·공중 출격·웨이브 공중전·착륙 훈련 모드는 제거했습니다. 메뉴 배경만 활주로 장면을 씁니다.)

엘리트·전설 정책도 실제 조종은 에이스와 같은 정밀 조종 법칙(양력벡터·G 명령, 기총 추적)과 안전장치(지형 회복·공중 충돌 회피)가 맡고, 정책은 0.1초마다 기동(양력벡터 방향·G·스로틀·기총 추적 여부)을 고릅니다 (아래 '강화학습 AI').

시험 결과 (실게임 브라우저, 120초, 무작위 머지, 기총전, `rl/harness.js`):
- 엘리트(약화 전설) vs 전설 12판 → 0승 4패 8무 (전설 피격 0)
- 엘리트(약화 전설) vs 에이스 12판 → 1승 0패 11무 (엘리트 피격 0) — 에이스 < 엘리트 < 전설
- 이전 엘리트(v1 반복 231, `src/elite_policy.json`, 지금은 쓰지 않음) vs 에이스 36판 → 31승 0패 5무
- 에이스(규칙 기반)의 기총 추적 법칙 개선 후, 수평 선회만 반복하는 상대도 격추 (이전에는 무승부)

## 조작

옵션: CAS, G 효과, 무한 연료, **무한 탄약**(기관포·플레어/채프 자동 보충, 미사일은 미사일 허용 난이도에서만), 사운드.

메뉴는 임무 브리핑형 좌측 패널(난이도 목록·조작 방식·그래픽 품질·옵션, 하단 "출격" 버튼 고정)이다. 마우스 감도·피치 반전은 '감도 · 반전' 접힘 패널, 키 표는 '조작표' 접힘 패널 안에 들어 있다. 피치 반전·마우스 감도·그래픽 품질 등 메뉴 설정은 브라우저에 저장됩니다.

### 커스텀 조작 (키·마우스 설정)

'커스텀' 옆 **키·마우스 설정…** 버튼으로 엽니다 (`src/keybind.js`, 설정은 localStorage `f15sim.custom.v1`).
- 동작 34개(비행·엔진·무장·시스템·시점·표시)마다 키나 마우스 버튼(좌·우·휠·4·5번)을 **2개까지** 지정. 칸을 누르고 키를 누르면 지정, Esc 취소, Backspace/Delete 지우기. 이미 다른 동작에 쓰인 키는 그 동작에서 옮겨 옴.
- **프리셋에서 불러오기**: 배틀필드식(키보드/마우스)·클래식 배치를 시작점으로 복사.
- **스로틀 방식**: MIL까지 + 애프터버너 키 누름(배틀필드식) / 연속(MIL에서 멈춤, 다시 누르면 A/B, 클래식식).
- **마우스**: 마우스 비행 켜기(포인터 잠금), 좌우 이동 = 롤 또는 러더, 감도, 상하 감도 배율, 중립 복귀 강도(0 = 스틱이 그 자리에 머묾), 상하 반전.
- Esc는 항상 일시정지입니다.

### 배틀필드식 키보드 비행 (기본)

방향키를 누르는 동안 스틱이 점점 깊게 들어가고, 떼면 곧바로 중립으로 돌아옵니다(짧게 톡 = 미세 조정, 길게 = 최대 기동). 플레이어 기체의 피치는 **피치레이트 명령·자세 유지** 방식이라 키를 떼면 기수가 그 자리에 멈춥니다(0.2초 탭 = 기수 약 1~2° 이동 후 정지, 되돌아오는 출렁임 없음). 오래 누르면 G가 올라가 9 G에서 제한됩니다. 날개가 60° 이내로 서 있을 때 스틱을 놓으면 그 기수 자세가 만드는 **비행경로(수평 ±2° 이내면 수평)를 유지**하므로, 스로틀을 줄이면 고도를 지킨 채 실제로 감속합니다(F-15는 항력이 작아 아이들만으로는 300 KCAS에서 초당 약 1.5 kt, 스피드브레이크를 펴면 약 3.5~9 kt 감속).

### 배틀필드식 마우스 비행

게임 화면을 클릭하면 마우스가 잠기고(포인터 록) 마우스로 피치/롤을 조종합니다. 마우스를 움직인 만큼 스틱이 기울고 멈추면 중립으로 돌아옵니다. 나머지 키는 키보드 비행과 같고(방향키는 보조), Alt 또는 휠 클릭을 누른 채 마우스를 움직이면 둘러봅니다. Esc를 누르면 마우스가 풀리면서 일시정지됩니다.

## 공대공 레이더 (우측 하단 스코프)

- 기수 기준 ±60° 방위, ±40° 고각을 좌우로 스캔합니다(120°를 약 1.6초에 왕복). 빔이 지나가는 순간에만 탐지 판정을 하고, 탐지된 표적은 트랙(위치·속도·고도)으로 표시되며 갱신되지 않으면 8초에 걸쳐 흐려지다 사라집니다.
- 탐지 거리 약 100 km(54 NM). 저고도 표적을 내려다보면 지면 클러터로 70 km로 줄고, 산에 가린 표적은 잡히지 않습니다.
- **육안 접촉**: 10 km 이내에서 지형에 가리지 않은 적은 레이더 빔 밖(후방 포함)이어도 노란 마름모로 표시하고, 스코프 밖이면 테두리 화살표로 방향을 알려줍니다. 근접 기총전에서 적이 어디 있는지 바로 보입니다.
- Q(클래식: T)로 록온하면 STT로 전환되어 안테나가 표적만 추적합니다. 근거리(10 NM 이내, 기수 30° 안)의 보이는 적은 트랙 없이도 바로 록됩니다(ACM 모드). 스코프 아래에 거리·고도·접근속도(Vc)가 표시되고, 기수 65° 밖으로 벗어나거나 지형에 1.5초 이상 가리면 록이 풀립니다.
- 거리 눈금은 기본 **AUTO**: 가장 가까운 적이 스코프 안쪽에 들어오도록 2 / 5 / 10 / 20 / 40 / 80 NM 중에서 자동 선택합니다(1:1 기총전에서는 보통 2~5 NM). `=` 키로 수동 눈금 ↔ AUTO 전환. 아군 미사일은 흰 점, 접근하는 적 미사일은 점멸 표시.

## 적 추적 시점

R(클래식: L, 게임패드: 오른쪽 스틱 누르기)을 누르고 있는 동안 내 기체 뒤-위에서 가장 가까운 적(록 중이면 록 표적)을 바라보는 시점이 됩니다. 내 기체는 화면 아래, 적은 화면 가운데에 오므로 선회전에서 적의 위치와 자세를 놓치지 않습니다. C로 '적 추적' 시점을 고정할 수도 있고, 조종석 시점에서는 고개만 적에게 돌립니다.

## 그래픽

- **하늘·대기** (`src/world.js`): 물리 기반 하늘(레일리/미 산란, `rayleigh`·`mieCoefficient`·`mieDirectionalG`). 지평선 쪽 하늘 색과 안개 색을 같은 색 객체(`uFogColor`)로 공유해 경계가 어긋나지 않고, 태양 방위에 따라 따뜻함·차가움을 섞는다. 안개는 고도 지수 감쇠(해면 소광계수 + 척도고도, `THREE.Fog` 재해석).
- **지형** (`src/world.js`, 120 km): 절차적 알베도 맵에 밭 모자이크(방향성 줄무늬 + 잡음 흔들림), 도메인 워핑 fbm으로 뭉친 숲 캐노피, 균열·암석 질감. 근거리 노멀 디테일 3단 합성(`uNormalDetail`). 호수·바다는 수심 맵으로 가·중앙·깊은 물 색을 나누고 해안 거품과 수심 0 근처 알파 페이드로 경계를 지운다. 구름은 적운 무리(인스턴스 퍼프, 태양 방향 조명·근접 페이드·원→근 정렬)와 별도 권운 층. 나무 45,000그루 인스턴싱.
- **기체** (`src/aircraftModel.js`): 부품별 고세그먼트 절차적 F-15C. USAF 2톤 위장 + 패널선·리벳·풍화를 캔버스로 그려 map·normalMap·roughnessMap으로 쓰는 PBR 스킨(무광 도료, 약한 클리어코트). 흡입구 램프, 노즐(수렴형 외곽 통 + 터키 페더 이음 15줄 + 안통·터빈면·애프터버너 발광판), 캐노피·조종석 내부(계기판·스틱·시트), 조종면·기어·노즐·애프터버너 화염 애니메이션.
- **폭발·파티클** (`src/effects.js`): 다단계 폭발(순간 섬광 + 점광원 → 불덩이 → 연기 기둥 25초, `FX.SMOKE_LIFE`), 파편(연기 꼬리 방출, `FX.TRAIL_*`), 충격파 링, 피격 스파크, 흙먼지·물보라·베이퍼 콘. 미사일 흰 연기는 전용 시스템(`wsmoke`, 12000). 조정 노브: `FX` 상수 묶음(지름·지속·바람 `SMOKE_WIND`·감쇠 `SMOKE_FADE`).
- **무장 시각 표현** (`src/weapons.js`, 판정에는 영향 없음): 미사일 연기 리본(연소 중에만 방출, 간격보다 굵게 찍어 틈 없는 궤적, AIM-120·R-77은 저연기 `TRAIL_FX.low*`), 노즐 화염 스프라이트(연소 중에만 표시), 예광탄 리본(앞끝은 HDR 밝기·뒤끝은 어둡고 가늘게 테이퍼).

## 물리 모델 (src/flightmodel.js, src/f15.js)

- **강체 6-DOF**: 오일러 강체 방정식(Ixz 교차항 포함) + 쿼터니언 자세 적분, 240 Hz 고정 간격 서브스텝

- **대기**: ISA 1976 (대류권/성층권), 보정대기속도(CAS)는 피토 공식(초음속은 레일리 공식)으로 계산

- **엔진**: F100-PW-220 ×2, 코어 스풀 지연(아이들→MIL 약 4초), 애프터버너 점화 지연, 밀도/램 효과 추력 감률, 흡입구 온도·연소실 압력 제한, 추력비연료소모율 기반 연료 소모, 좌우 비대칭 추력
- **조종계통**: CAS ON은 비선형 동적역변환(NDI) 제어법칙(9 G·받음각 30° 제한, 안정축 롤, 선회 협조, 중량에 따른 G 제한 감소). 플레이어 기체는 스틱 = 피치레이트 명령 + 놓으면 기수 정지 후 비행경로 유지(목표 자세 = 목표 경로 + 현재 속도의 트림 받음각 → 감속해도 경로가 내려가 고도를 속도로 바꾸지 않음; 받음각 증가율 제한, 스태빌레이터 작동 속도를 고려한 피치 각가속도 제한), AI 기체는 스틱 = 하중배수(G) 명령. CAS OFF는 스태빌레이터 직결로 G 제한이 없어 과하중 시 기체가 파손됨. 구동기 속도 제한 포함
- **랜딩기어**: 스프링-댐퍼 3점 지지, 구름/제동/횡 마찰, 앞바퀴 조향, 침하율 초과 시 기어 파손, 테일 스트라이크
- **기타**: 구조 한계(+13.5 / −6.5 G), 과속 손상, G-LOC 모델(누적 G 부하, 그레이아웃 → 의식 상실)

- **적 AI**: 플레이어와 같은 비행 모델을 스틱/스로틀 입력으로만 조종합니다 (에이스·엘리트·전설은 추력·G 한계 보정).
  - **전설: 정밀 BFM** — 매 프레임 기하로 판단합니다. 기동 탐색 플래너·교리 규칙 기반 버전도 만들어 같은 시드로 비교했지만, 사람처럼 계속 최대 G로 도는 상대에게는 '리드 추적 + 최대 G'를 정확하게 실행하는 쪽이 가장 강해서 이 구조를 택했습니다.
    - 공세: 상대 리드점(1.2초 앞)으로 최대 G 리드 추적, 받음각 27°(에너지 유지). 접근률이 거리에 비해 크면(목표 접근률 = (거리−300)/3, 30~200 m/s) 스로틀을 줄이고 스피드브레이크, 그래도 오버슛이면 래그점 기준 45° 위로 최대 G 하이 요요
    - 정밀 기총 추적(`trackNose`, 기수 직접 지향): 롤은 조준점을 양력면(속도벡터와 조준점이 이루는 면)에 넣고, G는 받음각 목표 α* = 조준점이 속도벡터에서 떨어진 각 + 0.7·변화율을 CL 표로 G 명령으로 바꿔 줌(FCS가 정확히 그 받음각으로 역산), 오차 2° 이내면 러더로 좌우 수정. 이전 법칙(중력 보상까지 넣은 가속도 방향으로 롤, 경로 회전율 제어)은 양력면이 조준면에서 기울어 2~3° 고정 오차가 남고 루프가 과민해 진동했음 → 선회·반전 표적 8가지 시험에서 사격 허용 오차 안에 있는 시간 3% → 94% (`rl/track_test.py`). 수평 선회만 반복하는 상대도 이제 마무리함
    - 정면 교차: 상대가 내게 거는 리드 오차를 계산해 사격 해(6°)가 잡히면 먼저 회피, 아니면 통과 약 4초 전부터 상대가 지나갈 쪽으로 수평 80° 경사 최대 G 리드 턴
    - 수세: 받음각 30°로 최대 브레이크(평면 선회 반경이 같아져 수평 선회 반복으로는 기총 해가 안 나옴), 사격 해 직전 선회면 전환
    - 지형: 현재 속도·하강각에서의 당겨 올림 고도(V²/(g(n−1))·(1−cosγ))로 필요한 고도만 확보, 1·2초 앞 지형도 확인
  - 조향: 목표 방향의 회전 각속도로 필요한 G를 미리 계산해 당김(오차가 쌓인 뒤에야 당기는 지연 제거, 기량에 비례 적용)
  - 전설의 기총 방어: 공격자가 내게 거는 리드 조준을 계산해 사격 해가 잡히기 직전(5°)에만 선회면을 100~160° 전환, 그 외엔 공격자 쪽 최대 G 브레이크, 가까이서 빠르게 붙으면 감속해 오버슛 유도. 정면 교차에서도 상대 기수가 내게 사격 해를 잡으면(6°, 1.8 km 이내) 선회면을 바꿔 정면 사격을 피함
  - 상황 판정: 기하(ATA·AA·거리·접근률)로 공세 / 중립 / 수세를 판단
  - 공세: 리드·퓨어·래그 추적, 하이/로 요요, 오버슛 방지, 기총 추적(PD 제어 + 표적 G 피드포워드), 스냅샷
  - 중립: 정면 교차 시 리드 턴, 남는 속도는 경사 상승 선회로 고도에 저장, 느리면 기수를 낮춰 가속
  - 수세: 브레이크 선회, 기총 방어 재킹, 오버슛 유도, 언로드 가속, 수직 브레이크

## 강화학습 AI (rl/) — 엘리트·전설 난이도

엘리트·전설 난이도의 근접전 기동은 강화학습(PPO 셀프플레이)으로 학습한 정책이 맡습니다(`src/elite_policy.json`, `src/legend_policy.json`; 파일이 없으면 에이스와 같은 규칙 기반 AI).

- **시뮬레이터 이식** (`rl/sim.py`): 게임의 비행 모델(6자유도, 공력표, 엔진, G 명령 CAS/NDI)을 numpy로 옮겨 수천 대를 한꺼번에 적분. 같은 조종 입력으로 12초 급기동 시 JS와의 위치 차이 1 cm 이내 (`rl/parity.py`).
- **환경** (`rl/env.py`): 1:1 기총전. 물리 240 Hz, 조종 60 Hz, 정책 결정 10 Hz. 정책은 양력벡터 방향(상대 쪽 기준 각), G, 스로틀/스피드브레이크, 기총 추적 여부를 고르고, 실제 조종은 게임 AI와 같은 정밀 조종 법칙(flyLiftP, trackNose)이 수행. 사격은 리드 오차 기준 자동. 탄은 묶음 단위로 항력·중력·산포를 반영하고, 게임과 같은 피탄 타원체로 명중 판정(산포 4×4 표본).
- **보상**: 준 피해 − 받은 피해, 격추 ±5, 지면 충돌·과하중 −3, 위치 우위(ATA·AA)와 저고도 위험의 잠재함수 형상화(최적 정책을 바꾸지 않는 형태).
- **상대**: 현재 정책끼리 셀프플레이, 과거 정책 풀, 사람식 리드 추적 봇, 수평 선회 반복 봇, 수직 기동 봇, 고정된 엘리트, 사람 대결 기록으로 모방 학습한 사람 봇. 양쪽 성능(전설 보정 유무)을 무작위로 섞어 학습.
- **시작 조건**: 머지·중립·한쪽 공세에, 저고도(0.9~3 km)·저속(100~170 m/s)·기수 각도를 섞고 한 판 최대 240초로 길게 싸워 에너지 관리를 배우게 함.
- **학습** (`rl/train.py`, `rl/nn.py`): numpy만으로 구현한 PPO(MLP 256×256, GAE, Adam), 12개 프로세스 병렬. 평가 `rl/eval.py`, 브라우저용 내보내기 `rl/export.py`.
- **브라우저** (`src/rlpolicy.js`): 같은 관측·행동 정의를 JS로 옮겨 추론. 같은 상태에서 Python과 관측 차이 1e-7, 정책 출력 차이 1e-8.
- **사격 전 조준 유지**: 모든 AI는 조준점이 표적 위에 0.3초 연속으로 머물러야 쏩니다(`AIM_SETTLE`, 게임·학습 환경 공통). 정면 교차처럼 조준점이 스쳐 지나가는 사격은 어려워지고(정면 사격 피해 약 30% 감소) 꼬리 추적 사격은 거의 그대로입니다.
- **실게임 결과** (무작위 머지 출발, 120초 제한, 조준 유지 규칙 적용):
  - 엘리트(반복 231) vs 에이스: 16판 10승 0패 6무 (규칙 적용 전 44판 40승 0패 4무, 피격 0)
  - **전설 v2 (현재, 반복 1900)**: 무작위 환경(성능·무게·고도) 자가 대결 리그로 더 학습. 이전 전설(반복 550) 상대 게임 안 16판 5승 2패 9무, 시뮬레이터 게임 조건 96판 29승 6패 61무 / vs 엘리트 16판 8승 1패 7무 / vs 에이스 12판 3승 0패 9무(피격 0)

### v2: 큰 모델 + 커리큘럼 (rl/model.py, rl/train2.py)

- **모델**: 최근 0.9초 관측 4개(0.3초 간격)를 쌓은 입력(180) → 512-512-256 LayerNorm·SiLU 정책망. 가치망은 상대 관측까지 봄(225). 학습은 GPU(PyTorch), 시뮬레이션·추론은 CPU(numpy)·브라우저(JS).
- **0단계 증류** (`rl/distill.py`): 기존 전설을 DAgger로 큰 모델에 옮겨 같은 실력에서 시작.
- **1단계 기본기**: 시나리오(전체 교전 240초, 공세 마무리·수세 탈출 60초, 정면 머지·저고도 150초)를 성공률이 낮은 것 위주로 연습. 공세 마무리에는 회피(재킹·시저스) 봇.
- **2단계 리그**: 셀프플레이 25% + 이기기 어려운 상대 위주(PFSP)로 과거 스냅숏·기존 정책·봇·사람 모방 봇.
- **벤치마크** (`rl/bench.py`): 시나리오별 성공률과 주요 상대 전적. 증류 직후 61.6% → 반복 350 73.8%.
- 행동 잡음이 너무 작으면(증류로 물려받은 0.08) 학습이 멈추므로 하한 0.15를 둠.

## 개발 도구 (스크린샷·백업)

- `node rl/shot.mjs <출력폴더> <폭> <높이> <steps.json>` — 헤드리스 크롬 CDP 스크린샷(예: `rl/shot.mjs rl/gfx_review/ui_self 1280 720 rl/gfx_review/steps_ui_self.json`). steps는 `{"shot":"이름"}`(촬영), `{"js":"코드"}`(페이지에서 실행), `{"wait":ms}` 순서 목록.
- `rl/pm_view.js` — 촬영용 카메라 도구(페이지에서 `import('/rl/pm_view.js')` 후 사용). `pmStart(텔레메트리 표시 여부)`로 공중전 시작 + 궤도 카메라, `pmView(방위, 고각, 거리)`·`pmFix(거리)`로 고정, `pmBoom(크기)`으로 폭발 연출, `pmCam()`으로 원래 카메라 복귀.
- `rl/gfx_backup_20261119/` — 대개편 전 원본 백업(되돌릴 때 참고).
